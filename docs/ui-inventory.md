# Инвентарь интерфейса

Полный список экранов, состояний и элементов управления на момент начала
редизайна (Mantine, визуальный сброс с нуля). Это контракт «ничего не
потерялось»: каждый пункт должен найти себе место в новом макете, либо быть
осознанно снят с явного согласия.

Доменные термины — по `CONTEXT.md`. Русские строки — все до одной из `src/ru.ts`,
и редизайн их не переписывает: меняется расположение, а не формулировки.

## Общая рама

**Header (`app-header.tsx`)** — рендерится из корневого layout, три состояния:

- **Временный пароль**: имя приложения текстом (не ссылка), только «Выйти».
  Ни одной другой ссылки — все они вели бы обратно на ту же страницу.
- **Student**: имя приложения → `/courses` (не `/`), название открытого Course →
  `/courses/{id}`, «Выйти».
- **Admin**: то же плюс ссылка `/admin`; сам header и `main` на широкой мере
  (`--measure-wide`) внутри `/admin/*`.
- Не sticky (осознанно), нет сессии → header не рендерится вовсе.

**Layout**: preload трёх шрифтовых файлов, `lang="ru"`, `main` на `--measure`.

**403 (`forbidden.tsx`)**: заголовок «Урок закрыт», текст отказа, ссылка на
`/courses`.

## Student

### `/login`
Форма: логин, пароль, «Войти». Сообщение об ошибке над формой — три варианта:
неверные данные, блокировка на N минут, слишком часто (N секунд). Никогда не
называет, какое поле неверно. Без клиентского JS.

### `/password`
Один экран, два прихода: принудительный (временный пароль) и добровольный —
отличаются одной строкой лида и подписью первого поля. Поля: текущий/временный,
новый, подтверждение. Подсказка о длине, подсказка «остальные сессии выйдут».
Состояния: список отказов (`role="alert"`), успех + ссылка «Дальше». Без JS.

### `/courses`
Заголовок, строка «вы вошли как X» + бейдж Admin. Список Courses: название →
ссылка, язык · уровень. Пустое состояние.

### `/courses/[courseId]`
- Заголовок Course, строка «уровень · N уроков».
- **Lessons** — нумерованный список: открытый урок ссылкой, закрытый текстом с
  классом `locked`; статус — «закрыт» / «пройден» / «в процессе: k/n»; плюс
  «спорных: N», если есть.
- **Tests** — отдельным блоком (осознанно не среди уроков): название, количество
  Exercises, последняя Attempt с её счётом, метка «сдан/не сдан». Пустое
  состояние.
- Ссылка на `/courses/{id}/progress`.
- Побочный эффект: открытие делает Course текущим.

### `/lessons/[lessonId]` (Theory)
Заголовок, «грамматический фокус: …», отрендеренный markdown (`.theory`),
кнопка-ссылка «К практике», ссылка назад к Course.

### `/lessons/[lessonId]/practice` — главный экран
Шапка: ссылки на Course и на Theory, заголовок урока.

**Progress bar** (`.progress`): сегмент на Exercise, 8px, состояние передаётся
цветом + узором рельса + доступным именем. Под ней строка: «позиция k из n ·
пройдено N · с подсказкой N · спорных N».

**Вопрос** (`ExerciseQuestion`) — шесть Exercise Kind:
- `fill_gap`: инпуты стоят внутри предложения на местах `___`, по одному на Gap,
  `aria-label` с номером Gap. После вердикта инпуты заменяются на написанные
  слова, каждое помечено своим состоянием.
- `multiple_choice`: радиогруппа, имя группы своё на каждый Exercise.
- `word_order`: строка собираемого предложения, ряд кнопок-фрагментов
  (использованный становится невидимым, но не исчезает из потока), «Очистить».
- `composition` / `translation` / `open_writing`: textarea (3 или 6 строк).

**Фазы**:
- `answering`: «Проверить» + «Показать ответ» (если предложен). Отказ при пустом
  ответе.
- `checking`: строка статуса в том же ряду и на той же высоте, что кнопки —
  чтобы ответ не прыгал; через 60 секунд текст меняется на «всё ещё проверяю»;
  поток объяснения печатается по мере прихода.
- `result`:
  - `grading_failed` → VerdictLine состояния `failed`, два текста (занято / не
    работает). Никогда не выглядит как неверный ответ.
  - иначе VerdictLine correct/partial/incorrect со своими словами Practice,
    текст объяснения, «исправлено: …» (только с третьей неудачной попытки),
    блок Errors: тип ошибки, фрагмент, объяснение.
  - DisputeForm — только против судимого и не-correct вердикта.
  - Кнопки: «Дальше» (при correct или после спора) либо «Проверить» ещё раз,
    плюс «Показать ответ» когда предложен; подсказка, когда ещё не предложен.
- `revealed`: VerdictLine `help`, «правильный ответ: …», «Дальше».
- Практика завершена: progress + «урок пройден», далее либо «курс пройден», либо
  «следующий урок открыт» + кнопка; ссылка назад к Course.
- Пустая практика: «упражнений нет».

**DisputeForm** (общий с Test): закрытое состояние — фраза + кнопка «Не
согласен»; открытое — textarea с `maxLength`, отказ при пустом, «Отправить» /
«Отмена», состояние «отправляю»; после отправки — VerdictLine `disputed` с
разным текстом для Practice и для Test.

### `/tests/[testId]`
Заголовок, «N упражнений · порог M%», две строки-предупреждения (нет обратной
связи до отправки; Test ничего не гейтит). Все Exercises одним списком с
нумерацией позиции. Кнопка «Отправить», состояние «отправляю». Подтверждение при
неотвеченных: «N без ответа» + «Всё равно отправить» / «Продолжить отвечать»
(снимается, как только что-то ответили). Ошибка отправки. Ниже — список Attempts.
Ссылка назад к Course. Пустой Test — своё состояние.

### `/tests/[testId]/attempts/[attemptId]` (Review)
Ссылка назад к Test, заголовок, «название Test · попытка N», дата · порог.
- `scored`: крупный счёт + «сдан/не сдан».
- `grading` : строка статуса + объяснение; страница сама опрашивает сервер раз в
  4 секунды и останавливается, когда попытка отстоялась.
- `grading_failed`: VerdictLine `failed` + кнопка «Проверить ещё раз».
- Список Exercises: позиция · название состояния · кнопка «Показать/Скрыть».
  Верные свёрнуты по умолчанию, остальные раскрыты. Внутри: prompt; для
  детерминированных — список вариантов, где верный зелёный, выбранный неверный
  красный; «Ваш ответ» (для fill_gap — предложение с помеченными Gap, иначе
  жирным; «нет ответа» отдельно); объяснение; Errors; «Эталонный ответ»;
  DisputeForm или итог спора.

### `/courses/[courseId]/progress`
Ссылка на Course, заголовок. Для Admin — строка «смотрю запись X» и
`StudentPicker` (`<select>`, навигация через `?student=`).
- **Уроки**: на каждый — название, метка «закрыт», ProgressBar, «N% · k/m/n · спорных N».
- **Итог по Course**: крупный процент + разбивка.
- **Histogram ошибок**: таблица «тип ошибки / количество», бар + число. Пустое состояние.
- **Изменение во времени**: два `<select>` (от/до урока), SVG-график с шестью
  сериями (цвет + пунктир + маркер), подписи серий, дублирующая таблица,
  примечание «тесты не учитываются». Состояния: нет уроков, нет ошибок.
- **Attempts**: список со ссылкой, датой и счётом; «проверяется» и «не оценено»
  (сбой грейдинга) помечены отдельно.

## Admin

### `/admin`
- **HealthBanner** — 4 состояния (never / healthy / unhealthy / stale), каждое со
  своим тоном и рельсом; строка «последний запуск, кем, сколько занял»; при
  неуспехе — причина и три догадки (credentials / egress красным, rate limit
  приглушённым). Читается из записи, не запускает вызов.
- **Courses** — все Courses системы: язык · уровень · N уроков; модель Grader.
- **NewCourseForm**: название, язык, уровень (+подсказка), модель Grader
  (+подсказка), EffortSelect. Модель следует за языком, пока Admin не выберет
  свою. Отказы списком кодов. Кнопка со состоянием «создаю».
- **ImportCourseForm**: подсказка, файловый инпут, состояния «импортирую» /
  общий сбой / список кодов отказа / успех с числом уроков, тестов, картинок,
  пропущенных картинок, примечанием «никто не записан» и ссылкой на курс.
- Четыре ссылки: аккаунты, споры, guidance, health.

### `/admin/students`
Список аккаунтов: имя, бейдж Admin, число Enrollments, дата создания, пометка
временного пароля. Удаление в два нажатия (кнопка превращается в
предупреждение + «Удалить» / «Отмена»); свой аккаунт и Admin удалить нельзя —
вместо кнопки объясняющая строка. Форма нового аккаунта: имя + «Создать».
Панель выданного временного пароля: моноширинный, крупный, с двумя примечаниями
(показывается один раз; аккаунт до смены ничего не может). Отказы, общая ошибка,
уведомление об удалении.

### `/admin/disputes`
Очередь ожидающих (старые сверху): ссылка «Открыть», от кого и из какого Course,
дата, prompt Exercise. Ниже — решённые, с меткой ruling. Ниже — панель
Coherence Guard: «сработал N из M», «заставил correct», «запретил correct», и
отдельное состояние, когда судить ещё нечего. Пустые состояния для обоих списков.

### `/admin/disputes/[disputeId]`
Ссылка назад, заголовок, строка «от кого · из урока/теста · когда».
Секции: Exercise (prompt + Reference Answer), Accepted Variants (плоским списком
или по Gap, если Gap больше одного), ответ Student (+ вердикт, объяснение,
корректировка Grader — здесь показывается всегда), Errors Grader, комментарий
Student (VerdictLine `disputed`).
`ResolveDispute`: при нескольких кандидатах — fieldset с радио «за какой Gap»
и подсказка; кнопки «Принять» / «Отклонить» с двумя поясняющими строками;
после решения — VerdictLine с ruling, строка о добавленном варианте (с самим
словом и номером Gap), ссылка назад. Уже решённый спор кнопок не показывает.

### `/admin/guidance`
Три поясняющих абзаца, textarea (12 строк, maxLength), подсказка о лимите,
строка провенанса (поставляется с приложением / отредактировал X тогда-то),
кнопки «Сохранить» и «Вернуть исходный текст» со своими busy-состояниями,
отказы, статус «сохранено».

### `/admin/health`
HealthBanner, объяснение, кнопка «Запустить проверку» (busy), результат:
healthy/unhealthy, длительность, причина, три догадки. Ссылка назад.

### `/admin/courses/[courseId]`
Заголовок, «язык · уровень · модель Grader», ссылка на settings.
- **Lessons**: ссылка, статус публикации (черновик / опубликован / есть
  неопубликованные изменения), число Exercises, кнопки «Вверх»/«Вниз»
  (оптимистичный порядок с откатом при отказе).
- **Новый Lesson**: поле названия, примечание «начинается черновиком», кнопка.
- **Tests**: список со статусом публикации и числом Exercises; форма нового Test.
- **Roster**: все Students, «Записан» / кнопки «Записать» / «Отчислить»
  (обратимо, без подтверждения — осознанно).
- Ссылка экспорта Course (обычная ссылка, отдаёт файл) + подсказка.
- Отказы, ошибка, уведомления.

### `/admin/courses/[courseId]/settings`
Название (редактируемо), язык и уровень — текстом, не отключёнными контролами,
плюс объясняющая строка. Модель Grader (`<select>`, без Haiku по ADR 0002) +
подсказка. EffortSelect. Секция Course Instruction: два поясняющих абзаца,
textarea (10 строк, maxLength) + подсказка о лимите. Отказы, «сохранено»,
кнопка со состоянием.

### `/admin/lessons/[lessonId]` (Draft editor)
Заголовок, «Course · N упражнений», объяснение.
- Строка состояния: не сохранено / есть неопубликованные изменения / всё
  опубликовано; отдельно «никогда не публиковался»; метка происхождения Draft
  (`.madeBy`) — генерация / доработка / вручную.
- Поля: название урока, грамматический фокус (+подсказка), Theory (textarea).
- `ImageUpload`: файловый инпут со своим лейблом-состоянием, подсказка о размере,
  вставка markdown-ссылки в Theory, ошибка.
- `ExerciseList` — на каждый Exercise: номер, Kind, кем судится, пометка «есть
  Submissions», `<select>` Kind (смена Kind требует подтверждения и говорит, что
  будет отброшено), prompt (+подсказка про `___` у fill_gap), Reference Answer
  (+две разные подсказки), «учитывать регистр» + подсказка, поля Accepted Answers
  (по Gap, если Gap несколько; для word_order — «принимаемые порядки»), поля
  вариантов (`ChoiceFields`: строка варианта, радио «эталонный», чекбокс
  «верный», «убрать», «добавить вариант/фрагмент»), кнопки «Вверх»/«Вниз»/
  «Убрать» (удаление с Submissions требует подтверждения). Кнопка «Добавить
  упражнение».
- `GeneratePanel` (сворачиваемая): тема, словарь, число упражнений (+границы),
  микс Kind (по строке на Kind), «продолжить с урока N» (`<select>`), пожелания,
  ModelAndEffort, потоковый вывод Theory (`.streaming`), кнопки «Сгенерировать»/
  «Отмена»/«Назад к черновику», сообщение о расхождении заказанного и полученного.
- `RefinePanel`: объяснение, требование сначала сохранить, список прошлых
  обращений, поле сообщения (+подсказка), ModelAndEffort, «Отправить»/«Отмена»,
  сообщение о потере треда.
- Кнопки «Сохранить» и «Опубликовать»; публикация непроверенной генерации
  требует подтверждения и называет число Exercises с нетронутым Reference Answer.
- Предпросмотр Theory (`.theory`), ссылка на историю, ссылка назад.

### `/admin/lessons/[lessonId]/history`
Список Drafts (новые сверху, нумерация от старого): номер, дата, происхождение,
автор, число Exercises, метка «опубликован», текст обращения для Refinement,
«Показать» / «Выбран». Для выбранного: кнопка «Восстановить» (говорит, что
добавляет версию и не публикует), Theory, список Exercises со всем содержимым —
Kind, кем судится, prompt, Reference Answer, варианты/фрагменты, принимаемые
ответы, «учитывать регистр». Пустые состояния. Ссылка назад.

### `/admin/tests/[testId]`
Заголовок, «Course · N упражнений · опубликован/нет», два поясняющих абзаца.
Поля: название, порог сдачи (+подсказка). Тот же `ExerciseList`. Кнопки
«Сохранить» / «Опубликовать» (публикация только после сохранения, о чём есть
строка). Отказы, «сохранено». Ссылка назад.

## Сквозные элементы

- **Шесть состояний Verdict** (`verdict-state.ts`): correct, partial, incorrect,
  help, disputed, failed. Три способа различения одновременно: цвет, узор рельса,
  русское слово. Потребители: Practice, Test review, ProgressBar, Disputes,
  список Attempts.
- **VerdictLine** — единственная сборка «состояние + слова + пояснение».
- **FaultList / faultMessage** — коды отказов везде рендерятся одинаково.
- **EffortSelect** — один контрол на все три места, где спрашивают Effort.
- **`.actions`** — ряд кнопок/ссылок; **`.muted`** — пояснения; **`.ok` / `.error`**
  — статусы; **`.prompt` / `.given` / `.corrected` / `.feedback` / `.errors`** —
  словарь показа ответа и разбора.
- Локаль дат: `ru.locale`, форматирование на сервере там, где иначе была бы
  ошибка гидратации.
